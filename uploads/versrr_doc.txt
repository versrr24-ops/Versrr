1.2 Typography


Font: Inter (Google Fonts). Fallback: system-ui, sans-serif.


Headings: text-xl (20px) bold for page titles. text-lg (18px) semibold for section headers.


Body: text-sm (14px) for most content. text-xs (12px) for timestamps and captions.


Numbers/Money: font-mono for all amounts and rates. Ensures digits align visually.


1.3 Global Layout (Mobile-First)

Mobile viewport: 375px minimum width. Everything designed for this first, then scales up.

Top bar: Fixed. Height 56px. Dark (#111827). Left: Versrr logo (V mark). Right: notification bell icon + profile avatar/icon. Tapping profile opens dropdown menu.

Bottom navigation: Fixed. Height 64px. Dark (#111827) with top border (#374151). Five tabs:
P2P

Active tab: Purple icon + purple label. Inactive tabs: gray-500 icon + label. Each tab has a simple icon above the label (use Lucide icons).

Main content area: Scrollable area between top bar and bottom nav. Padding 16px horizontal. Background #111827.

Desktop (>768px): Bottom nav moves to a left sidebar. Content area expands. Same components, more breathing room.


1.4 Component Patterns


Cards: bg-gray-800 rounded-xl border border-gray-700 p-4. Used for offers, trades, Lock Trades, bids.


Buttons (Primary/CTA): bg-amber-500 text-gray-900 font-semibold rounded-lg py-3 px-6. Hover: bg-amber-400. Used for all money actions.


Buttons (Secondary): bg-purple-800 text-white rounded-lg py-3 px-6. Hover: bg-violet-600. Used for non-money actions.


Buttons (Outline): border border-gray-600 text-gray-300 rounded-lg py-3 px-6. Used for Cancel, Decline, secondary options.


Inputs: bg-gray-800 border border-gray-700 rounded-lg p-3 text-gray-50. Focus: border-purple-800 ring-1 ring-purple-800.


Badges: Verified = bg-purple-800/20 text-purple-400 text-xs px-2 py-1 rounded-full. Funded = bg-emerald-500/20 text-emerald-400. Not Funded = bg-gray-600/20 text-gray-400.


Modals: Centered overlay with bg-black/60 backdrop. Modal body bg-gray-800 rounded-2xl p-6 max-w-md.


Toast notifications: Slide in from top. Success = green left border. Error = red left border. Auto-dismiss 4 seconds.


Empty states: Centered icon (gray-600) + text explaining what goes here + CTA button. Never show blank white/dark screens.


Loading: Skeleton shimmer on cards (bg-gray-700 animate-pulse rounded). Never use spinners alone.

2.2 P2P Marketplace (Default Tab)

P2P Home / Browse Offers

Route: /p2p

Toggle at top: BUY | SELL (pill-style toggle, active = amber background)

Create Offer

Route: /p2p/create

Purpose: Vendor creates a public marketplace offer.


Form fields: Direction (Buy/Sell toggle), Asset (USDT/USDC), Rate (number input with currency label), Min Amount, Max Amount


Payment Methods: multi-select from approved list (Bank Transfer, Opay, PalmPay, Kuda, Mobile Money, etc.)


Offer Terms: text area for vendor’s custom terms (displayed to buyer before trade opens)

Open Trade (Buyer View)

Vendor’s terms displayed in a highlighted box (purple-bg/10)

Step 1 — H (I Have): select card type from list (Apple, Amazon, Google Play, Steam, iTunes, Sephora, Nike, etc.), enter card value, upload card image (optional at this stage)


Step 2 — W (I Want): enter desired rate percentage (e.g. 75%). Helper text: ‘Vendors will bid at or above your rate.’

H&W Listing Detail (Card Holder View)

Route: /hw/:id

Purpose: Card holder watches bids come in and accepts one.


Listing summary card: card type, value, desired rate, time remaining (countdown)


Bids list: each bid shows vendor name + verification count, offered rate (highlighted if above desired), funded status badge, bid time


Bids sorted by rate (highest first)


For each bid: ‘Accept’ (amber) button


On accept: if vendor is funded, escrow locks and trade opens. If not funded, vendor gets 3-minute funding window. If vendor fails to fund, next highest bidder is offered the trade.


After trade opens: standard trade flow with added step — card verification. Vendor verifies card balance before releasing crypto.


Listing auto-closes when bidding window expires if no bid is accepted

Purpose: Vendor sees a card listing and places a bid.


Card details: type, value, desired rate, card holder’s verification count, time remaining


Bid form: Rate input (pre-filled with desired rate as minimum), Terms text area


Funded status: if vendor has enough balance to cover the trade at their bid rate, auto-tagged ‘Funded.’ If not, tagged ‘Not Funded — you’ll have 3 minutes to fund if accepted.’

3. Critical User Flows


3.1 First-Time Buyer Flow (Unverified User)


User signs up (email + phone + name).


User deposits USDT to their unique address. Balance appears in wallet.


User goes to P2P tab. Sees offers. Some offers show ‘Verified users only’ — these are grayed out with tooltip explaining why.


User taps an offer that accepts unverified users. Enters amount. Sees vendor terms. Taps ‘Buy USDT.’


Trade opens. Escrow locks. Vendor is notified.


Vendor engages. Shows payment details. User sends fiat payment.


User taps ‘I Have Paid.’ If first-time: prompted to submit KYC (photo of ID matching their declared name). Sensitive data can be redacted.


Vendor sees buyer’s name + submitted KYC. Verifies name matches payment sender. Clicks ‘Verify Identity’ then ‘Release.’


Trade completes. Buyer receives crypto. Buyer’s profile now shows: ‘Verified by 1 vendor.’


Buyer can now access ‘Verified users only’ offers. After 15 verifications, eligible to become vendor.


3.2 Vendor Lock Trade Flow (Multi-User)


Vendor goes to LK tab → ‘Create Lock Trade’ → selects ‘I’m Selling.’


Sets rate, min/max, writes offer note and terms. No expiry. Taps ‘Create.’


Gets shareable link. Shares on WhatsApp trading group.


User A clicks link. Sees offer details (rate, terms, min/max). Enters $100. Taps ‘Open Trade.’ If not logged in, redirected to sign up first.


System checks vendor’s available balance ≥ $100. Locks $100 from vendor’s available balance. Trade opens.


User B clicks same link. Enters $200. System checks vendor’s remaining available balance. Locks $200. Second trade opens.


Vendor sees both trades in LK management screen. Handles each independently — same flow as any P2P trade.


Vendor can pause or delete the Lock Trade at any time. Existing open trades continue but no new ones can be started.


3.3 H&W Gift Card Flow


User goes to H&W tab → taps ‘+ I Have a Card.’


Selects Apple Gift Card, enters $100 value, sets desired rate 75%, sets 10-min bidding window. Posts listing.


All verified gift card vendors receive notification (push + Telegram).


Vendor A bids 76%. Vendor B bids 78%. Vendor C bids 80%. User sees all bids, sorted by highest rate.


Vendor C shows ‘Funded’ badge (has enough balance). User accepts Vendor C’s bid.


$80 USDT locked from Vendor C’s available balance (80% of $100). Trade opens.


In trade chat, user shares gift card details. Vendor verifies card balance. If valid, vendor clicks ‘Verify Identity’ then ‘Release.’ User receives $80 USDT.


If card is invalid/partially redeemed: vendor files dispute with evidence.


3.4 User-Created Lock Trade (Buyer Seeking Vendors)


User goes to LK tab → ‘Create Lock Trade’ → selects ‘I’m Buying.’


Enters: ‘I want $500 USDT’ + offer note: ‘Paying via bank transfer, need fast release.’ Posts it.


Shares link in Telegram vendor group.


Vendor A opens link. Sees request details. Bids rate ₦1,600/USDT + terms. Shows ‘Funded’ badge.


Vendor B bids ₦1,580/USDT. Shows ‘Not Funded’ badge.


User sees both bids. Accepts Vendor A (funded, better rate).


$500 USDT locked from Vendor A’s balance. Trade opens with standard flow.


If user had accepted Vendor B (not funded): Vendor B gets 5-minute notification to fund. If funded in time, trade opens. If not, user can accept another vendor.

5. Implementation Notes for Claude Code


Dark mode is the default. Every component should be styled for dark first. Use Tailwind’s dark: prefix only if you also support light mode. For MVP, dark only is fine.


Mobile first. Build every screen at 375px width first. Then add responsive breakpoints for tablet (768px) and desktop (1024px+).


All money amounts use font-mono. Rates, balances, trade amounts — anything with numbers should use monospace font for digit alignment.


All CTA buttons are amber. Any button that involves money (Fund, Release, Pay, Accept, Withdraw, Deposit) is bg-amber-500. Non-money actions use purple.


Verification badges everywhere. ‘Verified by N peers’ should appear on offer cards, trade screens, Lock Trade pages, H&W bids, and profiles. It’s the trust signal. Make it visible.


Error states are mandatory. Every API call needs a loading state, a success state, and an error state. Never leave a screen blank or hanging.


Copy patterns from existing fintech apps. Binance’s trade flow, Wise’s transfer flow, Kuda’s dashboard. These are patterns your users already understand.


Test with real content lengths. A vendor name might be 3 characters or 25. An offer note might be 10 words or 200. Terms might be 1 line or 10. Design for the range, not the ideal.
